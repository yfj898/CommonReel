## 6. 采用的最小工作方式

1. **先给可观察的完成条件。** 当前任务以 2–4 人房间流程、硬条件、导入与画像生命周期、真实 MCP、本地模型失效后的表单路径为准；从已有 SPEC 读取，避免重写需求。
2. **把校验放在真实入口。** 解析外部输入、校验模型工具参数、供应事实和房间权限；内部传递已建立的类型和业务结果。失败保留原因和当前状态。
3. **修真实问题。** 先复现，定位一条有因果的调用链，改必要实现，并增加能失败的行为回归；检查通过即进入剩余流程，不无故重复跑检查。
4. **浏览器走完一场电影夜。** 创建、加入、共享限制、历史导入或跳过、推荐、提议、逐成员记录、保存、重开与结束；分别观察空结果、供应过期、并发修改、模型不可用的恢复。
5. **拆开证据。** 稳定回归用受控供应和模型；真实 API 与真实本地模型另作小样本运行；电脑窄屏不计物理手机，工程通过不计小组满意度。

本次调研没有要求更新全局设置、增加 skill、引入服务或注册账户。下一步应由完整测试发现的实际断点决定修复位置；新增规则只有在能改变后续具体行为时才进入长期约定。
