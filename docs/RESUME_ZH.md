# CommonReel 项目描述

项目定位：面向多人观影决策的 Go MCP 服务，参加 Amazon Build, Ship, Shape
2026 Alexa+ 赛道的作品开发。正式提交前，不写“已参赛提交”或获奖经历。

可采用的简历内容

- 针对多人偏好冲突与共享状态更新问题，设计 Go MCP 选片服务，将成员偏好、
  类型否决、片单解释及选择留痕封装为 9 个工具，通过 MCP 2025-11-25
  Streamable HTTP 支撑网页模拟助手与外部兼容客户端。
- 使用 SQLite 事务、房间版本号与请求内容绑定的幂等键处理并发修改和不确定
  重试，测试验证 20 个相同请求仅产生一次状态变更，并拒绝过期片单保存。
- 基于 MovieLens 1M 的 100 万条评分，采用全局时间划分、中心化用户协同过滤
  与先验融合；在固定抽样的 200 名合格用户上，NDCG@10 从热门基线的
  0.1316 提升至 0.1566，候选规模为每人 1991–3135 部未评分影片。
- 将成员硬否决与组内最低预估匹配分纳入排序，提供平均分和热门排序对照、
  SSE 多窗口更新及解释收据；多人满意度尚需真实用户测试。

指标边界：离线单人排序评测，非生产指标；构造的三人组回放不等于人类
满意度实验。延迟报告为本机进程内测量，不能写成线上接口 P95 或生产 QPS。
这轮使用 AI 辅助开发；面试前应能独立讲清协议、事务、相似度及数据划分。
